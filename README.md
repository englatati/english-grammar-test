# english-grammar-test

Адаптивный статический тест из 50 вопросов для предварительной диагностики **грамматики** английского. HTML, CSS и JavaScript без зависимостей, сборки, backend и регистрации. Вопросы и ключ перенесены из задания без изменений.

## Запуск

Из каталога репозитория:

```sh
sh scripts/serve.sh
```

Откройте сайт через HTTP на порту 8000. Открытие `index.html` через `file://` не подходит для JavaScript-модулей. Перезапуск страницы сбрасывает ответы. Установка npm-пакетов не требуется.

Для запуска в облачной среде независимо от терминальной сессии:

```sh
nohup sh scripts/serve.sh >/tmp/english-grammar-test-server.log 2>&1 </dev/null &
curl --fail http://127.0.0.1:8000/
```

Preview должен использовать порт **8000**. Другой порт можно задать через `PORT=3000 sh scripts/serve.sh`. Сервер слушает `0.0.0.0`, чтобы принимать запросы от прокси среды. Если порт занят, сначала проверьте ответ сервера; не запускайте второй процесс поверх первого. Лог фонового сервера находится в `/tmp/english-grammar-test-server.log`. После восстановления среды процесс нужно запустить заново.

## Публикация

- **GitHub Pages:** Settings → Pages → Deploy from a branch, выбрать ветку с проектом и `/ (root)`.
- **Netlify:** опубликовать корневой каталог проекта, без команды сборки.
- **Vercel:** Framework Preset → Other, без команды сборки, Output Directory → `.`.

Все пути относительные, поэтому сайт работает и в подпапке GitHub Pages. Сервер должен отдавать `.js` с корректным JavaScript MIME-типом. Домен и публичная публикация настраиваются на выбранном хостинге.

## Структура

- `index.html`, `styles.css` — семантический интерфейс и адаптивный дизайн.
- `questions.js` — вопросы, четыре варианта и индекс правильного ответа.
- `scoring.js` — подсчёт по четырём блокам и выбор самого высокого доступного уровня.
- `results.js` — расшифровки уровней.
- `app.js` — навигация, выбор ответа, результат и полный сброс.

Ответы находятся только в памяти текущей вкладки. Нет cookies, аналитики, внешних шрифтов, запросов к API или постоянного хранилища. Ключ не отображается в интерфейсе, но доступен в исходниках: у статического клиентского теста его невозможно скрыть от просмотра кода.

## Проверки

```sh
node --test tests/scoring.test.mjs
# При работающем локальном сервере; требуется Python Playwright и /usr/bin/chromium:
python3 tests/browser.py
```

Тесты сверяют все 50 ключей с заданием, проверяют все 30 976 комбинаций баллов блоков, запрет повышения при проваленной базе и браузерный сценарий на ширинах 320, 390 и 1440 px: клавиатура, запрет перехода без ответа, возврат, полный проход, результат и повторный проход после сброса. Также проверяется отсутствие внешних запросов, cookies и browser storage.

## Ограничения диагностического материала

У каждого вопроса один назначенный ключ, но некоторые формулировки допускают другие ответы при ином контексте. Например, в №6 `Did you work from home?` тоже грамматически корректно; в №28 `She studied English for three years` корректно для завершённого периода; в №45 включённый свет сам по себе не исключает `must have gone to bed`. Для более однозначной диагностики эти вопросы стоит отдельно отредактировать с преподавателем. Исходное задание здесь сохранено.

Пороговые условия также сохранены буквально: A2+ присваивается только при 8–9 баллах B1, B1+ — только при 5–6 баллах B2. Поэтому повышение балла сложного блока без выполнения всех условий следующего уровня может убрать знак «+». Это предусмотрено заданными правилами, а не вычислительная ошибка.
